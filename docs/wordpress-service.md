# Experimental WordPress service

`modules/wordpress.nix` wraps the WordPress module in the locked Nixpkgs revision. It is disabled by default and is not yet an installation workflow. It serves one configured hostname, uses the upstream `twentytwentyfive` theme, has no plugins by default, and disables code changes and automatic code updates in WordPress. Update those packages through Nix after testing. Normal content and media are intended to remain writable.

The service uses the `wordpress` Unix account for PHP-FPM and a local MariaDB database. The upstream module creates the database and grants access to that account. Authentication uses the MariaDB Unix socket; TCP networking is disabled and no database password is put in a Nix configuration. The upstream service generates WordPress authentication keys at runtime in `/var/lib/wordpress/<hostname>/secret-keys.php`. The upstream default upload and font directories are under the same site directory. MariaDB uses `/var/lib/mysql`. These paths must be backed up or recreated as appropriate before any future release. The current repository does not yet implement backup, restore or a complete WordPress setup.

The production mode enables Nginx ACME and HTTPS. An instance must configure the ACME terms and contact information, and DNS must point at the VM. The optional `localHTTP` mode listens on `127.0.0.1:80` only and is for local development. It must not be exposed as a public service. Neither mode is an acceptance-tested deployment profile.

The virtual host returns HTTP 503 until `/var/lib/wordpress/<hostname>/initialized` exists. A future authorized initializer must verify WordPress installation and create this marker as the WordPress service user only after a successful install. It must not trust a marker alone as proof of a valid database. Do not create the marker manually on a deployment. The Nginx configuration blocks the public install and setup scripts, protects `wp-config.php`, and places the upload PHP deny rule ahead of the general PHP handler. These rules and their ordering need an integration test against the final combined Nginx configuration.

`tests/wordpress.nix` is a NixOS VM test for the gate, local listener, database networking and HTTP restrictions. It creates the marker only to exercise the restrictions after the gate; this is not a WordPress installation, restore, TLS or complete MVP test. It can be exposed as a flake check by the integration work. Run it from a development environment with a supported Nix daemon and virtualization; TCG may be substantially slower than KVM.
